Process Management: States, PCBs, and Lifecycle

A process is a program in execution: it consists of the program's code, its current activity represented by the value of the program counter and processor registers, and an associated set of resources such as memory, open file handles, and other allocations. The operating system is responsible for creating, scheduling, and terminating processes, and for maintaining the bookkeeping that lets it switch between many processes while giving each the illusion of having the CPU to itself.

Every process moves through a well-defined set of states during its lifetime. NEW: the process is being created (e.g. its PCB is being initialized) but has not yet been admitted to the pool of executable processes. READY: the process is loaded into main memory and is waiting to be assigned to the CPU; it is fully able to run but the scheduler has not yet dispatched it. RUNNING: the process's instructions are actively being executed by the CPU. BLOCKED (also called WAITING): the process cannot proceed until some event occurs, typically I/O completion, a resource becoming available, or a signal from another process; it is voluntarily giving up the CPU because there is nothing useful it can do until that event happens. COMPLETED (or EXIT): the process has finished executing normally. TERMINATED: the process has been stopped, either because it finished, crashed, or was forcibly killed (e.g. by the OS, a user, or a deadlock-recovery routine), and its resources are being reclaimed.

Transitions between these states follow strict rules that model real scheduling behavior. NEW moves only to READY (admission). READY moves to RUNNING when the scheduler dispatches it, or to TERMINATED if it is killed while still waiting. RUNNING can move to BLOCKED (it requests something unavailable), to COMPLETED (it finishes normally), back to READY (it is preempted, e.g. by a Round Robin quantum expiring or a higher-priority arrival), or to TERMINATED (it crashes or is killed). BLOCKED moves back to READY once the event it was waiting for occurs, or to TERMINATED if killed while blocked. COMPLETED and TERMINATED are both final states with no further transitions. Enforcing this state machine strictly -- rejecting any transition not in this list -- is what prevents inconsistent scheduler behavior, such as trying to "run" a process that was never admitted, or double-completing a process that already finished.

The Process Control Block (PCB) is the data structure the OS uses to represent and track a process. A PCB typically stores: a unique process identifier (PID); the current state; the program counter and saved CPU register values (so execution can resume exactly where it left off after a context switch); CPU scheduling information such as priority and pointers to scheduling queues; memory management information such as base/limit registers or page tables; accounting information like CPU time used and wall-clock start time; and I/O status information including open file lists and allocated devices. When the OS performs a context switch -- suspending one process and resuming another -- it saves the outgoing process's execution context into its PCB and restores the incoming process's context from its PCB, which is what makes multitasking possible on a single CPU core.

Process scheduling queues organize processes by state: the ready queue holds all processes in the READY state, typically implemented as the data structure the scheduling algorithm operates over (a plain FIFO queue for FCFS, a priority queue for priority scheduling, etc.), while one or more device/event queues hold BLOCKED processes waiting on specific resources or I/O completions. A long-term scheduler controls how many processes are admitted into the system (NEW to READY), a short-term scheduler (the CPU scheduler proper) decides which READY process runs next, and in systems that support swapping, a medium-term scheduler can suspend and later resume entire processes to manage memory pressure.
