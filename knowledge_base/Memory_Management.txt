Memory Management: Allocation and Fragmentation

Memory management is the operating system subsystem responsible for tracking which parts of main memory are in use, by which process, and for allocating and freeing memory as processes are created, grow, and terminate. Because physical memory is a finite, shared resource, the OS must satisfy each process's request only if enough free memory actually exists, and it must do so efficiently enough that allocation itself does not become a bottleneck.

A memory allocation failure occurs when a process requests more memory than the system currently has available. This is fundamentally different from the system being permanently out of memory -- it usually means the current allocation pattern has left insufficient contiguous or total free space for this particular request, even though enough memory may free up shortly as other processes complete and release their holdings. A well-behaved OS (and a well-behaved simulator like Procura) should detect this condition explicitly rather than crashing, and respond with a recovery strategy: for example, suspending a lower-priority process that is holding memory, reclaiming its allocation, and retrying the failed request once space is available.

Fragmentation is the classic pathology of memory allocation. External fragmentation occurs when free memory is broken into many small, non-contiguous blocks scattered between allocated regions -- there may be plenty of free memory in total, but no single block large enough to satisfy a new request. This typically results from repeated allocation and deallocation of variable-sized blocks over time. Internal fragmentation, by contrast, occurs when memory is allocated in fixed-size chunks (e.g. fixed pages or blocks) and a process's actual request is smaller than the chunk size, wasting the leftover space inside the allocated block. Classic allocation strategies for variable-sized partitions include first-fit (allocate the first free block big enough), best-fit (allocate the smallest free block big enough, minimizing leftover space but increasing fragmentation risk over time), and worst-fit (allocate the largest free block, leaving a larger, more usable remainder).

Paging is the dominant modern solution to external fragmentation: physical memory is divided into fixed-size frames, and a process's logical address space is divided into same-sized pages. Any page can be placed in any free frame, so a process's memory does not need to be contiguous, and a page table maps logical pages to physical frames transparently. This eliminates external fragmentation entirely (at the cost of some internal fragmentation in the last, partially-used page) and enables virtual memory: a process can be given the illusion of a large, contiguous address space even when physical memory is smaller, with inactive pages swapped out to disk. Segmentation is an alternative (or complementary) scheme that divides memory along logical program boundaries (code, stack, heap) rather than fixed sizes, which maps more naturally to how programs are structured but reintroduces external fragmentation between segments.

When a system is under memory pressure, an OS has several standard responses beyond simple denial: swapping (moving an entire blocked or lower-priority process out to disk to free its memory for others), page replacement algorithms (evicting individual pages that are unlikely to be needed soon, e.g. Least Recently Used), or -- in a simplified simulator context like this project -- suspending the lowest-priority memory holder and reclaiming its allocation so the requesting process can proceed, then resuming the suspended process once memory is available again.
